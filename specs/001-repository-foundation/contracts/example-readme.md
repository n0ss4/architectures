# Contract: Example README

Every example README MUST contain these sections, with these names, in this order. A section with
nothing to report MUST say so rather than be removed. Existing content, including credits, MUST be
kept in the most relevant section or in the optional sections at the end.

```markdown
# <Example name>

## Question answered
The architectural question this example answers, in one or two sentences.

## When to use it
Conditions under which this approach fits.

## When not to use it
Conditions under which it does not fit, and what to look at instead.

## Trade-offs
What this approach costs, linking to evidence for comparative claims.

## Domain coverage
| Area | Coverage | Notes |
|------|----------|-------|
| Catalog | full / partial / none | |
| Cart | full / partial / none | |
| Checkout | full / partial / none | |

## How to run it
Prerequisites, including versions, and exact install, build, and start commands.
All commands run from this example's directory unless a step says otherwise.

## Known limitations
Known defects, unverified setups, and anything intentionally left out.
```

Examples MAY add sections after `Known limitations`, such as `Architecture`, `Project structure`, or
`Credits`.
